# 작업 지도로 흐름 검증하기

- 기준 경로: FF › 디버깅 › 진단하기 › 작업 지도로 흐름 검증하기
- 원문: https://frontend-fundamentals.com/debug/pages/diagnose/map.html

## 원칙
복잡한 UI 상태, 비동기 요청, 사용자 입력 흐름은 단계별 작업 지도로 보면 실제 결과와 기대 결과를 비교하기 쉽습니다. 코드에서도 입력, 검증, 상태 변경, 렌더링 조건이 서로 맞물리는 순서가 확인 가능해야 합니다.

## 관찰 가능한 신호
- 입력 변경, validation, API 응답, 상태 갱신, 렌더링 조건이 한 흐름에 연결되어 있지만 단계별 결과가 검증되지 않습니다.
- boolean 상태 이름과 렌더링 조건이 반대로 쓰이거나, 정상/오류 UI 조건이 뒤집힐 수 있습니다.
- 비동기 응답 순서, stale state, 이전 입력값이 이후 렌더링에 섞일 수 있는데 흐름 검증이 없습니다.

## 게시 조건
- 변경된 코드에서 사용자 입력 또는 데이터 흐름의 단계가 3개 이상 이어집니다.
- 특정 단계의 기대값과 실제 사용값이 어긋나는 지점을 코드로 짚을 수 있습니다.
- 단계별 검증, 상태 이름 정리, 테스트 케이스 중 하나로 흐름을 더 분명하게 만들 수 있습니다.

## 억제 조건
- 단순 표시 변경이나 독립 함수 변경처럼 작업 지도를 그릴 만큼 흐름이 복잡하지 않습니다.
- 이미 테스트, story, QA 시나리오, 상태 머신 등으로 단계별 동작이 검증됩니다.
- 문제 가능성을 코드 위치가 아니라 일반적인 디버깅 조언으로만 말할 수 있습니다.
